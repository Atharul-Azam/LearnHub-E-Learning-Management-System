# Demo data (`python manage.py seed_demo_data`)

**Status: written, NOT yet executed.** Django could not be installed where this was built, so the command has never been run against a database. Only its pure-Python parts (the plan tables, the PDF/PNG generators) were executed. Run the command and the tests below, and report any error.

## Run it

```bat
python manage.py migrate
python manage.py seed_demo_data
```

The command prints a verification table computed from the database after seeding (PASS/FAIL per check) and exits with an error if any check fails. To re-check later without changing anything: `python manage.py seed_demo_data --check-only`.

Logins are written to **`DEMO_CREDENTIALS.local.md`** in the project folder (listed in `.gitignore`, excluded from release ZIPs) and the password is printed once in the console. The password is generated on the first run, never stored in the source code, and reused on later runs. Options: `--password X`, environment variable `DEMO_PASSWORD`, `--reset-demo-passwords`, `--credentials-file PATH`, `--allow-production`.

## What it creates

| What | Amount |
|---|---|
| Demo administrator | 1 (`admin@demo.learnhub.test`) |
| Approved teachers (verified, `TCH-` IDs) | 15 (`teacher01` .. `teacher15`; `teacher15` owns no course, to see the empty state) |
| Pending teachers (verified, awaiting approval) | 2 (`pending.teacher01/02`) |
| Students (verified, `STU-` IDs) | 55 (`student01` .. `student55`) |
| Courses | 17: 12 public (11 published + 1 hidden draft) and 5 private, owned by 14 different teachers, each drawn with a category cover by the interface (run `seed_demo_data --refresh-covers` to clear old demo thumbnails), 3 PDF materials and 2 assignments |
| Private-course invitations | one token per private course, with different expiries (never / 7 / 30 / 90 days) |
| Enrolments | about 20 per public course (students 01-03 are in all of them) |
| Private requests | pending, approved, rejected and revoked for every private course |
| Submissions | on time, late, reviewed with marks and feedback, and unreviewed |
| Progress | 0 %, partial and 100 % across enrolments |
| Also | announcements, discussion questions and replies (including an unanswered question per course), favourites, recently-viewed timestamps, notifications (read and unread), some dark-theme / serif-font preferences |

Every demo e-mail ends in `@demo.learnhub.test`; `.test` is a reserved domain, so mail can never reach a real person.

## Good accounts to start with

* **student01**: enrolled everywhere, every private-request state (approved, pending, rejected, revoked) plus one private course with *no* request so the invitation link can be tried (copy it from teacher's sharing page).
* **teacher01**: public course + private course with pending requests, submissions to review, an unanswered question.
* **admin@demo.learnhub.test**: administrator dashboard, user list, teacher requests (the two pending teachers).

## Safety guarantees (each has an automated test in `core/test_seed_demo.py`)

* Accounts are marked verified **only** by this command. The registration flow and the e-mail verification workflow are untouched, and the command sends no e-mail.
* Only accounts ending in `@demo.learnhub.test` are ever modified. Real users, their passwords and their data are not read or changed.
* Nothing is deleted or reset. Re-running adds only what is missing; existing demo passwords stay unless you pass `--reset-demo-passwords`.
* The command refuses to run when `DEBUG` is off (production settings) unless `--allow-production` is given. If you do seed a hosted site, those accounts and their shared password are publicly guessable targets: delete them afterwards (Django shell or the admin user list) or do not use that option.

## Not covered / limitations

* Dates are relative to the moment of the first run (deadlines "tomorrow", "in 6 days", and so on). Run it on a fresh database for the intended picture; later runs do not move them.
* Deadline-reminder notifications are generated by LearnHub when a student opens the dashboard, not by the seeder.
* Thumbnails and avatars are generated placeholders (colour + initials), not photographs. Students have no profile picture.
